## 1. RNN의 다양한 입출력 구조

RNN은 입력과 출력의 길이에 따라 여러 문제에 사용할 수 있습니다.

![RNN의 One-to-One Many-to-One Many-to-Many 구조](assets/lec11_01_rnn_io_structures.png)

| 구조 | 입력 | 출력 | 대표적인 용도 |
|---|---|---|---|
| One-to-One | 하나 | 하나 | 일반적인 예측 |
| Many-to-One | 여러 토큰 | 하나 | 문장 분류 |
| Many-to-Many | 여러 토큰 | 여러 토큰 | 번역·텍스트 생성 |

문장 분류에서는 전체 입력을 읽은 후 하나의 최종 결과를 만듭니다. 반면 생성에서는 여러 시점에 걸쳐 다음 토큰을 계속 출력합니다.

```text
분류: 여러 입력 토큰 → 하나의 범주
생성: 이전 토큰들 → 다음 토큰 → 갱신된 문맥 → 다음 토큰
```

## 2. 생성 문제와 다음 토큰 확률

언어 모델(language model)은 이전까지 등장한 토큰을 바탕으로 다음 토큰의 확률 분포를 계산합니다.

![이전 토큰으로 다음 토큰의 확률 분포를 계산하는 언어 모델](assets/lec11_02_next_token_probability.png)

예를 들어 다음 문맥이 있다고 가정하겠습니다.

```text
오늘 나는 학교에
```

모델은 다음 토큰 후보마다 서로 다른 확률을 출력합니다.

| 다음 토큰 후보 | 예시 확률 |
|---|---:|
| 갔다 | 0.55 |
| 도착했다 | 0.25 |
| 공부했다 | 0.15 |
| 기타 | 0.05 |

이를 다음과 같이 나타낼 수 있습니다.

$$
P(w_t \mid w_{<t})
$$

여기서 $w_t$는 현재 예측할 토큰이고, $w_{<t}$는 그보다 앞에서 등장한 모든 토큰입니다.

---

## 3. 문장 확률의 연쇄 분해

문장 전체의 확률은 각 시점의 다음 토큰 확률을 연결하여 계산합니다.

![각 시점의 다음 토큰 확률을 연결한 문장 확률](assets/lec11_03_chain_rule.png)

$$
P(w_{1:T}) = \prod_{t=1}^{T} P(w_t \mid w_{<t})
$$

짧은 문장으로 나타내면 다음과 같습니다.

```text
나는 책을 읽는다
```

$$
P(\text{나는, 책을, 읽는다})
= P(\text{나는})
\times P(\text{책을}\mid\text{나는})
\times P(\text{읽는다}\mid\text{나는, 책을})
$$

각 토큰은 앞에서 등장한 토큰을 문맥으로 사용합니다. 따라서 초반에 선택한 토큰이 이후의 확률 분포에도 영향을 줍니다.

## 4. 생성의 세 가지 핵심 개념

텍스트 생성에서는 Context Window, Generation Length, Autoregressive Loop를 구분해야 합니다.

![Context Window 생성 길이 자기회귀 반복의 관계](assets/lec11_04_generation_concepts.png)

| 개념 | 의미 |
|---|---|
| Context Window | 한 번의 예측에서 모델이 참고할 수 있는 입력 범위 |
| Generation Length | 앞으로 생성할 최대 토큰 수 |
| Autoregressive Loop | 생성한 토큰을 문맥에 붙이고 예측을 반복하는 과정 |

강의 자료에서는 생성 범위를 `Generation Horizon`으로 표현할 수도 있습니다. 실제 생성 코드에서는 주로 `max_new_tokens`와 같은 이름을 사용합니다.

```text
Context Window ≠ 생성할 토큰 수
```

문맥 범위가 32라고 해서 반드시 32개의 새로운 토큰을 생성하는 것은 아닙니다.

## 5. 자기회귀 생성의 작동 원리

자기회귀(autoregressive) 생성은 모델의 출력을 다시 입력 문맥에 추가하는 방식입니다.

![예측 토큰을 문맥에 추가하며 반복하는 자기회귀 생성](assets/lec11_05_autoregressive_loop.png)

```text
1단계: 오늘 나는 → 학교에 예측
2단계: 오늘 나는 학교에 → 갔다 예측
3단계: 오늘 나는 학교에 갔다 → EOS 예측
```

기본 생성 절차는 다음과 같습니다.

1. 현재 문맥을 모델에 입력합니다.
2. 다음 토큰의 확률 분포를 계산합니다.
3. 하나의 토큰을 선택합니다.
4. 선택한 토큰을 문맥 끝에 추가합니다.
5. 종료 조건을 만날 때까지 반복합니다.

생성은 일반적으로 다음 조건 중 하나를 만나면 종료합니다.

- EOS(End of Sequence) 토큰을 선택한 경우
- `max_new_tokens`에 도달한 경우
- 사용자가 정한 별도의 중단 조건을 만족한 경우

## 6. 분류와 생성의 구조적 차이

![하나의 결과를 내는 분류와 반복 출력하는 생성의 비교](assets/lec11_06_classification_generation.png)

| 항목 | 문장 분류 | 텍스트 생성 |
|---|---|---|
| 입력 | 전체 문장 | 현재까지의 문맥 |
| 출력 | 하나의 범주 | 다음 토큰의 확률 분포 |
| 반복 | 일반적으로 한 번 | 종료할 때까지 반복 |
| 이전 출력 사용 | 사용하지 않음 | 다음 입력 문맥에 추가 |
| 대표 평가 | Accuracy, F1-score | Loss, Perplexity, 생성 품질 |

분류 모델의 출력층이 범주 수만큼의 확률을 만든다면, 생성 모델의 출력층은 어휘에 포함된 모든 토큰 후보의 점수를 만듭니다.

```text
분류 출력: [batch, 범주 수]
생성 출력: [batch, time, 어휘 크기]
```

## 7. 학습과 추론의 차이

학습에서는 정답 문장을 알고 있지만, 추론에서는 정답이 없습니다.

![정답 토큰을 사용하는 학습과 예측 토큰을 사용하는 추론](assets/lec11_07_training_inference.png)

### 학습 데이터 만들기

정답 문장을 한 칸 이동하여 입력과 목표를 구성합니다.

```text
원문: 나는 학교에 간다

입력: 나는   학교에
목표: 학교에 간다
```

| 시점 | 모델 입력 | 예측 목표 |
|---|---|---|
| 1 | 나는 | 학교에 |
| 2 | 학교에 | 간다 |

### 추론하기

추론에서는 모델이 선택한 토큰을 다음 입력으로 사용합니다.

```text
초기 문맥 → 모델 예측 → 예측 토큰 추가 → 다시 예측
```

따라서 초기에 잘못된 토큰이 선택되면 이후 문맥도 달라질 수 있습니다.

## 8. Teacher Forcing과 Exposure Bias

Teacher Forcing은 학습할 때 모델이 예측한 토큰이 아니라 정답 토큰을 다음 시점의 입력으로 사용하는 방법입니다.

![Teacher Forcing과 추론 시 오류 누적 과정](assets/lec11_08_teacher_forcing_exposure_bias.png)

```text
모델 예측 → 정답과 비교 → Loss 계산
정답 토큰 → 다음 시점의 입력
```

예측값과 정답의 역할을 구분해야 합니다.

- 예측값 $\hat{y}_t$: 정답 $y_t$와 비교하여 손실을 계산합니다.
- 정답 $y_t$: 학습 시 다음 시점의 입력으로 사용합니다.

Teacher Forcing은 학습을 안정적으로 만들지만 학습과 추론 사이에 차이를 만듭니다.

| 단계 | 다음 입력으로 사용하는 토큰 |
|---|---|
| 학습 | 정답 토큰 |
| 추론 | 모델이 생성한 토큰 |

이 차이 때문에 추론 시 모델이 자신의 잘못된 출력을 계속 입력으로 받으면서 오류가 누적될 수 있습니다. 이를 **노출 편향(Exposure Bias)**이라고 합니다.

```text
학습: 정답 → 정답 → 정답 → 안정적인 문맥
추론: 예측 → 오류 → 달라진 문맥 → 추가 오류 가능성
```

## 9. 긴 문장 생성의 한계

생성이 길어질수록 다음 문제가 나타날 수 있습니다.

- 초기 문맥의 중요한 정보를 잊을 수 있습니다.
- 같은 표현을 반복할 수 있습니다.
- 초기에 발생한 오류가 뒤쪽으로 누적될 수 있습니다.
- 문법적으로 맞지만 전체 의미가 일관되지 않을 수 있습니다.

LSTM과 GRU는 기본 RNN보다 긴 정보를 다루기 쉽도록 설계되었지만, 매우 긴 문맥을 항상 안정적으로 유지하는 것은 아닙니다. 이후 강의에서는 Encoder–Decoder, Attention, Transformer가 이 문제를 어떻게 개선하는지 살펴봅니다.

## 10. 간단한 자기회귀 생성 의사 코드

다음 코드는 자기회귀 생성의 구조를 보여주는 간단한 예시입니다.

```python
generated = start_tokens.copy()

for _ in range(max_new_tokens):
    x = np.array([generated[-max_len:]])
    prob = model.predict(x, verbose=0)[0, -1]
    next_id = int(np.argmax(prob))

    generated.append(next_id)

    if next_id == eos_id:
        break
```

핵심은 `next_id`를 `generated`에 다시 추가하는 부분입니다. 다음 Lecture 12에서는 이 과정을 문자 단위 LSTM으로 구체화합니다.

## 핵심 정리

- 언어 모델은 이전 토큰을 바탕으로 다음 토큰의 확률을 계산합니다.
- 자기회귀 생성은 선택한 토큰을 문맥에 추가하며 예측을 반복합니다.
- Context Window는 참고 범위이고, `max_new_tokens`는 최대 생성 길이입니다.
- 학습에서는 정답 토큰을, 추론에서는 모델의 예측 토큰을 다음 입력으로 사용합니다.
- Teacher Forcing은 학습을 안정시키지만 학습과 추론 사이의 차이를 만듭니다.
- Exposure Bias는 추론 중 초기 오류가 이후 문맥에 누적되는 현상입니다.
- 다음 Lecture 12에서는 Keras LSTM으로 문자 단위 텍스트 생성을 살펴봅니다.
