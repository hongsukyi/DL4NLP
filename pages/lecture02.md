# Lecture 02. 자연어 처리를 위한 텍스트 전처리

텍스트 전처리(text preprocessing)는 사람이 작성한 문장을 딥러닝 모델이 처리할 수 있는 입력으로 준비하는 과정입니다. 이번 강의에서는 문장을 토큰으로 나누고, 토큰을 숫자 ID로 바꾸며, 여러 문장의 길이를 맞추는 전체 흐름을 살펴봅니다.

## 학습 목표

이번 강의를 마치면 다음 내용을 설명할 수 있습니다.

- 텍스트 전처리가 필요한 이유를 설명할 수 있습니다.
- 단어, 형태소, 서브워드 토큰화의 차이를 구분할 수 있습니다.
- 영어와 한국어 토큰화의 특징을 설명할 수 있습니다.
- 정제, 정규화, 불용어 처리의 목적을 설명할 수 있습니다.
- BPE의 기본 원리를 설명할 수 있습니다.
- 정수 인코딩, 패딩, 잘라내기의 역할을 구분할 수 있습니다.

---

## 1. 텍스트 전처리란?

딥러닝 모델은 사람이 작성한 문장을 그대로 계산할 수 없습니다. 먼저 문장을 일정한 단위로 나누고, 각 단위를 숫자로 바꿔야 합니다. 여러 문장을 한 번에 처리하려면 입력 길이도 일정하게 맞춰야 합니다.

![문장이 모델 입력으로 변환되는 전처리 과정](https://cdn.jsdelivr.net/gh/hongsukyi/DL4NLP@main/assets/lec02_01_preprocessing_pipeline.png)

텍스트 전처리의 기본 흐름은 다음과 같습니다.

```text
문장 → 토큰화 → 정수 인코딩 → 길이 맞추기 → 모델 입력
```

예를 들어 다음 문장을 처리한다고 가정해 봅시다.

```text
나는 오늘 항구를 순찰했다.
```

전처리를 거치면 문장은 토큰으로 나뉘고, 각 토큰은 숫자 ID로 변환됩니다. 입력 길이가 정해져 있다면 부족한 위치에는 패딩 토큰을 추가합니다.

> **핵심:** 전처리는 텍스트의 의미를 학습하는 과정이 아니라, 텍스트를 모델이 사용할 수 있는 입력으로 준비하는 과정입니다.

---

## 2. 토큰과 토큰화

**토큰(token)**은 모델이 처리하는 텍스트의 기본 단위입니다. 문장을 토큰으로 나누는 과정을 **토큰화(tokenization)**라고 합니다.

![단어, 형태소, 서브워드 토큰화 비교](https://cdn.jsdelivr.net/gh/hongsukyi/DL4NLP@main/assets/lec02_02_tokenization_types.png)

문장은 여러 기준으로 나눌 수 있습니다.

| 토큰 단위 | 설명 | 간단한 예 |
|---|---|---|
| 단어 | 공백이나 규칙에 따라 단어 단위로 분리 | `학교에` |
| 형태소 | 의미나 문법 기능을 가진 최소 단위로 분리 | `학교` + `에` |
| 서브워드 | 자주 사용되는 단어 조각으로 분리 | 토크나이저의 어휘집에 따라 달라짐 |
| 문자 | 한 글자씩 분리 | `학` + `교` + `에` |

같은 문장도 토큰화 방법에 따라 결과가 달라질 수 있습니다. 어떤 방법이 항상 가장 좋은 것은 아니며, 언어의 특징과 사용하는 모델에 맞게 선택해야 합니다.

---

## 3. 영어 토큰화: 공백만으로 충분할까?

영어 문장은 단어 사이에 공백이 있어 비교적 쉽게 나눌 수 있습니다. 그러나 축약형과 문장부호까지 고려하면 단순한 공백 분리만으로는 충분하지 않습니다.

![영어의 공백 토큰화와 규칙 기반 토큰화](https://cdn.jsdelivr.net/gh/hongsukyi/DL4NLP@main/assets/lec02_03_english_tokenization.png)

다음 문장을 살펴봅시다.

```text
It's home-based.
```

단순히 공백으로 나누면 다음과 같습니다.

```text
["It's", "home-based."]
```

규칙 기반 토크나이저는 축약형, 하이픈, 마침표 등을 별도의 토큰으로 처리할 수 있습니다.

```text
["It", "'s", "home-based", "."]
```

실제 결과는 사용하는 토크나이저의 규칙에 따라 달라집니다. 중요한 것은 학습과 추론에서 같은 토크나이저와 같은 어휘집을 사용하는 것입니다.

---

## 4. 한국어 토큰화가 어려운 이유

한국어는 영어와 달리 조사와 어미가 단어에 붙어 나타납니다. 따라서 공백만 기준으로 나누면 문법적인 정보와 의미 단위를 충분히 구분하기 어렵습니다.

![한국어 어절을 형태소로 나누는 과정](https://cdn.jsdelivr.net/gh/hongsukyi/DL4NLP@main/assets/lec02_04_korean_morpheme.png)

다음 표현을 비교해 봅시다.

```text
학교에
학교에서
학교를
```

세 표현에는 모두 `학교`가 포함되어 있지만, 뒤에 붙은 조사에 따라 문장 속 역할이 달라집니다.

```text
학교 + 에
학교 + 에서
학교 + 를
```

한국어 토큰화가 어려운 주요 이유는 다음과 같습니다.

- 명사에 조사와 어미가 붙습니다.
- 하나의 어절 안에 여러 형태소가 포함될 수 있습니다.
- 띄어쓰기가 항상 일정하지 않습니다.
- 문맥에 따라 형태와 의미의 해석이 달라질 수 있습니다.

---

## 5. 형태소: 단어 안의 구조 살펴보기

**형태소(morpheme)**는 의미나 문법 기능을 가진 가장 작은 언어 단위입니다. 형태소 분석을 사용하면 하나의 어절 안에 포함된 의미 요소와 문법 요소를 구분할 수 있습니다.

예를 들어 다음 어절을 형태소 수준에서 살펴볼 수 있습니다.

```text
책을 → 책 + 을
들어갔다 → 들어가 + 았 + 다
```

형태소 분석 결과에서 어떤 요소를 남기거나 제거할지는 작업 목적에 따라 달라집니다. 조사와 어미가 항상 불필요한 것은 아닙니다. 문장의 관계나 시제처럼 중요한 정보를 제공할 수 있기 때문입니다.

> **주의:** 형태소를 많이 분리한다고 해서 항상 모델의 성능이 좋아지는 것은 아닙니다. 사용하는 모델과 토크나이저의 특성을 먼저 확인해야 합니다.

---

## 6. 한국어 형태소 분석 도구: KoNLPy와 Okt

**KoNLPy**는 Python에서 여러 한국어 형태소 분석기를 사용할 수 있게 해주는 라이브러리입니다. **Okt**는 KoNLPy에서 제공하는 분석기 중 하나로, 문장을 형태소로 나누거나 품사를 확인할 때 사용할 수 있습니다.

다음은 Okt로 문장을 형태소 단위로 나누는 간단한 예입니다.

```python
from konlpy.tag import Okt

okt = Okt()
sentence = "해양경찰이 항구를 순찰합니다."

tokens = okt.morphs(sentence)
print(tokens)
```

형태소와 품사를 함께 확인할 수도 있습니다.

```python
result = okt.pos(sentence)
print(result)
```

분석 결과는 도구의 사전과 분석 규칙에 따라 달라질 수 있습니다. 따라서 결과가 언제나 사람이 기대한 형태와 정확히 일치하는 것은 아닙니다.

---

## 7. 정제와 정규화

**정제(cleaning)**는 분석에 필요하지 않은 요소를 제거하거나 정리하는 과정입니다. **정규화(normalization)**는 서로 다르게 표현된 텍스트의 형식을 일정하게 맞추는 과정입니다.

![텍스트 정제와 정규화의 전후 비교](https://cdn.jsdelivr.net/gh/hongsukyi/DL4NLP@main/assets/lec02_05_cleaning_normalization.png)

| 구분 | 목적 | 예 |
|---|---|---|
| 정제 | 불필요한 요소 정리 | HTML 태그, 불필요한 공백 제거 |
| 정규화 | 표현 형식 통일 | 반복 문자나 표기 방식 통일 |

예를 들어 다음과 같은 변환을 생각할 수 있습니다.

```text
정제 전: <b>신고가   접수되었습니다.</b>
정제 후: 신고가 접수되었습니다.
```

```text
정규화 전: 너무 너무 좋아요!!!
정규화 후: 너무 좋아요!
```

정제와 정규화를 지나치게 적용하면 중요한 의미가 사라질 수 있습니다. 느낌표, 숫자, 대소문자, 반복 표현도 작업에 따라 중요한 정보가 될 수 있으므로 삭제 전에 목적을 확인해야 합니다.

---

## 8. 불용어: 자주 나오는 단어는 모두 지울까?

**불용어(stopword)**는 특정 작업에서 중요도가 낮아 분석 대상에서 제외할 수 있는 단어입니다. 한국어의 일부 조사나 매우 자주 등장하는 단어가 불용어 후보가 될 수 있습니다.

그러나 자주 등장한다는 이유만으로 무조건 삭제해서는 안 됩니다. 예를 들어 다음 두 문장에서 `않다`를 제거하면 의미가 크게 달라집니다.

```text
출항해도 된다.
출항하면 안 된다.
```

부정 표현을 제거하면 위험하거나 잘못된 판단으로 이어질 수 있습니다. 불용어 처리는 다음 사항을 고려해 결정합니다.

- 해결하려는 작업에서 해당 단어가 중요한가?
- 단어를 제거해도 문장의 핵심 의미가 유지되는가?
- 사용하는 모델이 원문 문맥을 그대로 활용하도록 학습되었는가?

Transformer 기반 사전학습 모델을 사용할 때는 모델이 학습할 때 사용한 토크나이저와 전처리 방식을 따르는 것이 일반적입니다.

---

## 9. 서브워드: 단어를 더 작은 조각으로 나누기

**서브워드(subword)** 토큰화는 단어 전체보다 작은 조각을 토큰으로 사용하는 방식입니다. 자주 등장하는 단어는 하나의 토큰으로 유지하고, 드문 단어나 새로운 단어는 알고 있는 조각으로 나눌 수 있습니다.

![서브워드 토큰화와 BPE의 병합 과정](https://cdn.jsdelivr.net/gh/hongsukyi/DL4NLP@main/assets/lec02_06_subword_bpe.png)

예를 들어 토크나이저가 `해양`, `경찰`, `순찰`과 같은 조각을 알고 있다면, 처음 보는 복합어나 변형된 단어도 여러 조각의 조합으로 표현할 수 있습니다.

서브워드 방식의 주요 장점은 다음과 같습니다.

- 어휘집에 없는 단어를 줄일 수 있습니다.
- 드문 단어도 알고 있는 조각의 조합으로 표현할 수 있습니다.
- 단어 단위 어휘집보다 어휘 수를 효율적으로 관리할 수 있습니다.

실제로 단어가 나뉘는 위치는 사용하는 토크나이저와 어휘집에 따라 달라집니다. 사람이 보기 좋은 형태와 모델이 사용하는 서브워드 경계가 항상 일치하지는 않습니다.

---

## 10. BPE: 자주 붙어 나오는 조각 합치기

**BPE(Byte Pair Encoding)**는 작은 단위에서 시작하여 자주 이웃하는 토큰 쌍을 반복적으로 합치는 서브워드 학습 방법입니다.

간단한 원리는 다음과 같습니다.

1. 단어를 작은 단위로 나눕니다.
2. 학습 데이터에서 서로 이웃한 토큰 쌍의 빈도를 계산합니다.
3. 가장 자주 등장하는 토큰 쌍을 하나의 새로운 토큰으로 합칩니다.
4. 정해진 횟수나 어휘집 크기에 도달할 때까지 병합을 반복합니다.
5. 새로운 문장에는 학습된 어휘집과 병합 규칙을 적용합니다.

예를 들어 `순`과 `찰`이 자주 함께 나타난다면 두 토큰을 `순찰`이라는 하나의 토큰으로 합칠 수 있습니다.

```text
순 + 찰 → 순찰
```

BPE는 새로운 문장을 볼 때마다 병합 규칙을 다시 학습하지 않습니다. 학습 데이터에서 미리 만든 어휘집과 병합 규칙을 새로운 문장에 적용합니다.

---

## 11. 정수 인코딩: 토큰에 번호 붙이기

토큰화가 끝나면 각 토큰을 숫자 ID로 바꿉니다. 이 과정을 **정수 인코딩(integer encoding)**이라고 합니다.

![어휘집을 이용해 토큰을 숫자 ID로 바꾸는 과정](https://cdn.jsdelivr.net/gh/hongsukyi/DL4NLP@main/assets/lec02_07_integer_encoding.png)

**어휘집(vocabulary)**은 토큰과 숫자 ID의 대응표입니다.

| 토큰 | ID |
|---|---:|
| `[PAD]` | 0 |
| `[UNK]` | 1 |
| 오늘 | 12 |
| 항구 | 35 |
| 순찰 | 48 |

다음 문장은 어휘집을 이용해 숫자 ID의 배열로 변환할 수 있습니다.

```text
오늘 항구 순찰 → [12, 35, 48]
```

정수 인코딩에서 기억해야 할 사항은 다음과 같습니다.

- 같은 어휘집에서는 같은 토큰에 같은 ID를 사용합니다.
- ID는 토큰을 구분하는 번호입니다.
- ID 사이의 숫자 차이는 단어의 의미 차이가 아닙니다.
- 어휘집에 없는 토큰은 `[UNK]`와 같은 특별 토큰으로 처리할 수 있습니다.

---

## 12. 패딩: 여러 문장의 길이 맞추기

문장마다 포함된 토큰의 수는 서로 다릅니다. 여러 문장을 하나의 배치(batch)로 묶어 모델에 입력하려면 입력 길이를 일정하게 맞춰야 합니다.

짧은 문장의 빈 위치에 `[PAD]` 토큰을 추가하는 과정을 **패딩(padding)**이라고 합니다.

![패딩과 잘라내기의 차이](https://cdn.jsdelivr.net/gh/hongsukyi/DL4NLP@main/assets/lec02_08_padding_truncation.png)

최대 길이를 5로 정했다고 가정해 봅시다.

```text
원래 입력: [오늘, 항구, 순찰]
패딩 결과: [오늘, 항구, 순찰, [PAD], [PAD]]
```

숫자 ID로 표현하면 다음과 같습니다.

```text
[12, 35, 48, 0, 0]
```

PAD는 실제 문장 내용이 아닙니다. 따라서 모델이 PAD 위치를 중요한 정보로 사용하지 않도록 마스크(mask)를 함께 사용할 수 있습니다.

```text
input_ids:      [12, 35, 48, 0, 0]
attention_mask: [ 1,  1,  1, 0, 0]
```

여기서 `1`은 실제 토큰 위치, `0`은 패딩 위치를 나타냅니다.

---

## 13. 패딩과 잘라내기는 다르다

**패딩**은 짧은 입력에 PAD 토큰을 추가하는 과정이고, **잘라내기(truncation)**는 최대 길이보다 긴 입력의 일부를 제거하는 과정입니다.

최대 길이가 5인 경우를 비교해 봅시다.

```text
짧은 입력: [A, B, C]
패딩 결과: [A, B, C, PAD, PAD]
```

```text
긴 입력:   [A, B, C, D, E, F, G]
잘라낸 결과: [A, B, C, D, E]
```

긴 문장을 잘라내면 중요한 정보가 사라질 수 있습니다. 앞부분과 뒷부분 중 어느 쪽을 유지할지는 모델과 작업 목적에 따라 결정해야 합니다.

| 구분 | 패딩 | 잘라내기 |
|---|---|---|
| 대상 | 최대 길이보다 짧은 입력 | 최대 길이보다 긴 입력 |
| 처리 | PAD 토큰 추가 | 일부 토큰 제거 |
| 목적 | 입력 길이 맞추기 | 입력 길이 제한하기 |

## 14. 전처리에서 결정할 세 가지

텍스트 전처리를 설계할 때는 다음 세 가지를 우선 결정해야 합니다.

### 1) 토큰 단위

문장을 단어, 형태소, 문자, 서브워드 중 어떤 단위로 나눌지 결정합니다. 사전학습 모델을 사용한다면 일반적으로 해당 모델과 함께 제공되는 토크나이저를 사용합니다.

### 2) 어휘집 크기

몇 종류의 토큰을 사용할지 결정합니다. 어휘집이 너무 작으면 많은 단어가 여러 조각으로 나뉘고, 너무 크면 메모리와 계산량이 증가할 수 있습니다.

### 3) 최대 길이

모델에 한 번에 입력할 토큰 수를 결정합니다. 최대 길이가 너무 짧으면 정보가 잘릴 수 있고, 너무 길면 패딩과 계산량이 증가합니다. 따라서 실제 데이터의 문장 길이 분포를 확인한 뒤 결정하는 것이 좋습니다.

> **핵심:** 토큰 단위, 어휘집 크기, 최대 길이는 서로 영향을 주므로 데이터와 모델을 함께 고려해야 합니다.

## 전체 전처리 흐름 확인

하나의 문장이 모델 입력으로 변환되는 과정을 다시 정리해 봅시다.

```text
1. 원문 확인
      ↓
2. 필요한 정제와 정규화
      ↓
3. 토큰화
      ↓
4. 정수 인코딩
      ↓
5. 패딩 또는 잘라내기
      ↓
6. input_ids와 attention_mask 생성
      ↓
7. 딥러닝 모델에 입력
```

## 핵심 정리

- 텍스트 전처리는 문장을 모델이 사용할 입력으로 준비하는 과정입니다.
- 토큰은 모델이 처리하는 텍스트의 기본 단위입니다.
- 한국어는 조사와 어미가 붙기 때문에 공백만으로 토큰화하기 어렵습니다.
- 형태소 분석은 어절 안의 의미 요소와 문법 요소를 구분합니다.
- 정제와 정규화는 의미가 손상되지 않는 범위에서 적용해야 합니다.
- 서브워드는 드문 단어를 알고 있는 작은 조각으로 표현할 수 있습니다.
- 정수 인코딩은 토큰을 식별 번호로 바꾸는 과정입니다.
- 패딩은 짧은 입력의 길이를 늘리고, 잘라내기는 긴 입력의 길이를 줄입니다.
- 토큰 단위, 어휘집 크기, 최대 길이는 데이터와 모델에 맞게 결정해야 합니다.
